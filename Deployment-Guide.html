Part A: Deploy the API on a VPS

1 Provision and Access the VPS

SSH into your VPS and create a dedicated non-root user:

# SSH into your VPS
ssh root@your-vps-ip

# Create a non-root user (recommended)
adduser deploy
usermod -aG sudo deploy
su - deploy

2 Install Node.js 20+ and pnpm

The project requires Node.js 20+ and pnpm 10.30.0 (pinned in package.json):

# Install Node.js 20 via NodeSource
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# Install pnpm (must match version 10.30.0 pinned in package.json)
sudo npm install -g pnpm@10.30.0

# Verify
node --version   # v20.x.x
pnpm --version   # 10.30.0

3 Install Build Tools for Native Modules

The better-sqlite3 package requires native C++ compilation:

sudo apt-get install -y build-essential python3

4 Install PM2 Process Manager

sudo npm install -g pm2

5 Clone the Repository

cd /home/deploy
git clone https://github.com/varunvraghavan87/agentic-momentum-trading.git
cd agentic-momentum-trading

6 Install Dependencies

pnpm install

This installs all workspace packages (apps/web, apps/api, packages/shared). The better-sqlite3 native module compiles during this step.

7 Build the API

cd apps/api
pnpm build

This runs tsup and outputs compiled JavaScript to apps/api/dist/index.js.

8 Create the .env File

cd /home/deploy/agentic-momentum-trading
cp .env.example .env
nano .env

Set these values for production:

# Required
TRADING_MODE=paper
NODE_ENV=production
API_PORT=3001
API_HOST=0.0.0.0
TZ=Asia/Kolkata
DATABASE_PATH=./data/db/trading.db

# Deployment - CRITICAL
WEB_URL=https://your-app.vercel.app
NEXT_PUBLIC_API_URL=https://api.yourdomain.com

# LLM (at least one needed for AI signal analysis)
ANTHROPIC_API_KEY=sk-ant-...
OPENAI_API_KEY=sk-...
LLM_PRIMARY=claude

# Zerodha (leave empty for paper mode)
KITE_API_KEY=
KITE_API_SECRET=

# Risk Parameters (defaults are sensible)
MAX_PORTFOLIO_DRAWDOWN=0.15
DAILY_LOSS_LIMIT=0.03
MAX_PER_TRADE_RISK=0.08
RISK_PER_TRADE=0.015
Critical: WEB_URL must match your exact Vercel deployment URL (including https://). This controls CORS. You'll set the real value after deploying the frontend in Part B.

9 Create the Data Directory

mkdir -p apps/api/data/db

The DB client auto-creates this directory, but creating it explicitly avoids permission issues.

10 Run Database Migrations

cd /home/deploy/agentic-momentum-trading
pnpm db:migrate

This creates all 8 SQLite tables: instruments, market_data, indicator_snapshots, trading_signals, orders, positions, portfolio_snapshots, backtest_runs.

11 Test the API Locally

cd apps/api
node dist/index.js
Expected output:
Server started on http://0.0.0.0:3001
Trading mode: paper
Registered cron: evening pipeline at 15:15 IST
Registered cron: morning execution at 09:14 IST

Test with curl in a separate terminal:

curl http://localhost:3001/api/health
# Expected: {"status":"ok","mode":"paper","db":"connected",...}

Press Ctrl+C to stop the test server.

12 Start with PM2

cd /home/deploy/agentic-momentum-trading
pm2 start ecosystem.config.cjs

The ecosystem.config.cjs is pre-configured with:

  • Process name: amt-api
  • Script: dist/index.js
  • Working directory: ./apps/api
  • Auto-restart on crash
  • Memory limit: 512 MB
  • Timezone: Asia/Kolkata

Verify:

pm2 status          # Should show amt-api as "online"
pm2 logs amt-api    # View live logs

13 Enable PM2 Startup on Boot

pm2 startup
# Follow the instructions it prints (copy-paste the sudo command)
pm2 save

14 Set Up Nginx Reverse Proxy with HTTPS

Install Nginx and Certbot:

sudo apt-get install -y nginx certbot python3-certbot-nginx

Create the Nginx configuration:

sudo nano /etc/nginx/sites-available/amt-api

Paste the following configuration:

server {
    listen 80;
    server_name api.yourdomain.com;  # Replace with your domain

    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}

Enable the site and obtain an SSL certificate:

sudo ln -s /etc/nginx/sites-available/amt-api /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

# Get SSL certificate (DNS must point to VPS IP first)
sudo certbot --nginx -d api.yourdomain.com

15 Configure DNS

In your domain registrar's DNS settings, create an A record:

TypeNameValue
Aapiyour-vps-ip-address

curl https://api.yourdomain.com/api/health

Part B: Deploy the Frontend on Vercel

1 Connect GitHub Repo to Vercel

  1. Go to vercel.com/new
  2. Click "Import Git Repository"
  3. Select the agentic-momentum-trading GitHub repo
  4. Vercel auto-detects the framework as Next.js from vercel.json

2 Configure Environment Variables

In the Vercel project settings → Environment Variables, add:

VariableValueEnvironment
NEXT_PUBLIC_API_URLhttps://api.yourdomain.comProduction
Note: This is the only environment variable needed for the frontend. It gets baked into the Next.js build at compile time and is used by apps/web/lib/api.ts for all API calls.

3 Verify Build Settings

Vercel reads vercel.json automatically. Confirm these settings in the dashboard:

SettingValue
Framework PresetNext.js
Build Commandcd apps/web && pnpm build
Output Directoryapps/web/.next
Install Commandpnpm install
Root Directory. (monorepo root)

4 Deploy

Click "Deploy". Vercel will:

  1. Run pnpm install (installs all workspace packages)
  2. Run cd apps/web && pnpm build (builds only the Next.js app)
  3. Deploy the .next output

The build excludes apps/api and data/ via .vercelignore.

5 Note the Vercel URL

After deployment, copy your Vercel URL (e.g., https://your-app.vercel.app or your custom domain).

6 Update VPS CORS with the Vercel URL

Back on your VPS, update the .env file with the real Vercel URL:

ssh deploy@your-vps-ip
cd /home/deploy/agentic-momentum-trading
nano .env

Set WEB_URL to your actual Vercel deployment URL:

WEB_URL=https://your-app.vercel.app

Restart the API to pick up the change:

pm2 restart amt-api
Critical: Without this step, the Vercel frontend will get CORS errors when calling the API.

Part C: Post-Deployment Verification

Run through this checklist to confirm everything is working:

1. Health Check

curl https://api.yourdomain.com/api/health
Expected: {"status":"ok","mode":"paper","db":"connected","cron":true,...}

2. Frontend Loads

Open https://your-app.vercel.app in a browser. The presentation site should load.

3. Dashboard Works

Open https://your-app.vercel.app/dashboard. It should show:

  • System status (green / connected)
  • Trading mode: Paper
  • Empty portfolio (no trades yet)
  • "No signals yet" (signals generate at 15:15 IST)

4. API Connectivity from Frontend

Open browser DevTools → Network tab. The dashboard makes 4 API calls on load:

  • GET /api/health
  • GET /api/dashboard/portfolio
  • GET /api/signals/today
  • GET /api/config

All should return 200 OK (not CORS errors).

5. Cron Jobs Registered

pm2 logs amt-api --lines 20

Look for:

Registered cron: evening pipeline at 15:15 IST
Registered cron: morning execution at 09:14 IST

6. Kill Switch Test

curl -X POST https://api.yourdomain.com/api/config \
  -H "Content-Type: application/json" \
  -d '{"killSwitch": true}'

Part D: Enabling Live Trading (When Ready)

1 Get Zerodha Kite Connect Credentials

  1. Register at developers.kite.trade
  2. Create an app to get your API Key and API Secret
  3. Set the redirect URL to: https://api.yourdomain.com/api/auth/callback

2 Update VPS Environment

nano /home/deploy/agentic-momentum-trading/.env

Change these values:

TRADING_MODE=live
KITE_API_KEY=your_api_key
KITE_API_SECRET=your_api_secret
pm2 restart amt-api

3 Daily Authentication

Kite access tokens expire daily. Each trading day you must re-authenticate:

  1. Get the login URL: 
    curl https://api.yourdomain.com/api/auth/login
# Returns: {"loginURL":"https://kite.zerodha.com/connect/login?..."}
  2. Open the login URL in your browser
  3. Log in with your Zerodha credentials
  4. The callback automatically exchanges the token
Important: The access token is stored in-memory only. If the API restarts (crash, PM2 restart, VPS reboot), you must re-authenticate.

4 Verify Live Connection

curl https://api.yourdomain.com/api/auth/status
# Expected: {"authenticated":true,"mode":"live"}

Troubleshooting

IssueSolution
CORS errors in browser console Ensure WEB_URL in VPS .env matches your exact Vercel URL (including https://). Restart API after changing.
Dashboard shows "Disconnected" Check API is running: pm2 status. Verify NEXT_PUBLIC_API_URL in Vercel env vars matches your API URL.
better-sqlite3 build fails on VPS Install build tools: sudo apt-get install -y build-essential python3
Cron jobs not firing Check TZ=Asia/Kolkata is set in .env. Check PM2 logs for cron registration messages.
"No signals" after 15:15 IST At least one LLM API key is required. Check ANTHROPIC_API_KEY or OPENAI_API_KEY is set and valid.
Kite auth fails Ensure redirect URL in Kite app settings matches https://api.yourdomain.com/api/auth/callback exactly.
DB locked errors SQLite WAL mode handles concurrent reads. If persistent, ensure only one API process is running (pm2 status).
Vercel build fails Check Vercel build logs. Common causes: missing NEXT_PUBLIC_API_URL env var, or pnpm version mismatch.
API won't start after update Run pnpm install then cd apps/api && pnpm build before pm2 restart.
